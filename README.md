## Быстрый старт

Нужен только **Docker Desktop**.

```bash
make up
```

Первый запуск занимает несколько минут: скачиваются образы и зависимости. Дальше:

| Адрес | Что это |
|---|---|
| http://localhost:8080 | Приложение |
| http://localhost:8025 | Mailpit — все письма платформы (коды подтверждения приходят сюда) |
| http://localhost:15672 | RabbitMQ, логин `guest` / `guest` — очереди и сообщения |
| http://localhost:8081 | Traefik — какие адреса в какой сервис ведут |
| http://localhost:8080/api/identity/docs | Документация API сервиса identity (аналогично для `notification`, `audit`) |
| `localhost:5433` | PostgreSQL, логин `postgres` / `postgres` |

Создать администратора:

```bash
make admin email=admin@testmatica.local
```

## Команды

```bash
make help            # все команды
make up / make down  # запустить / остановить
make logs s=identity # логи одного сервиса
make test            # все тесты
make test-identity   # тесты одного сервиса
make migration s=identity m="описание"  # новая миграция БД
make reset           # удалить все локальные данные и начать с чистого листа
```

Код сервисов и веб-клиента подключён в контейнеры напрямую: после сохранения файла сервис перезапускается сам.

## Структура

```
compose.yaml               локальное окружение целиком
libs/platform-common/      общий код сервисов: JWT, outbox/inbox, RabbitMQ, логи, ошибки
services/
  identity/                регистрация, вход, 2FA, роли, JWT
  notification/            письма и уведомления в интерфейсе
  audit/                   неизменяемый журнал всех событий
web/                       веб-клиент (Next.js)
infra/
  docker/                  общий Dockerfile Python-сервисов
  postgres/                создание баз для сервисов
docs/                      ТЗ-решения, план, архитектура
```

Каждый сервис устроен одинаково: `app/` (код), `migrations/` (Alembic), `tests/`.

## Как сервисы общаются

- Браузер → Traefik (`localhost:8080`) → `/api/<сервис>/...` → нужный сервис.
- Сервисы проверяют JWT сами, по публичному ключу identity (`/.well-known/jwks.json`).
- События («пользователь зарегистрировался») и команды («отправь письмо») идут через RabbitMQ.
  Сервис сначала записывает их в свою таблицу `outbox`, затем они уходят в брокер, поэтому ничего не теряется.
  Получатель помнит обработанные сообщения в таблице `inbox` и не выполняет одно сообщение дважды.
  Неудачные попытки повторяются 5 раз, затем сообщение попадает в очередь `<имя>.dlq` для разбора.
